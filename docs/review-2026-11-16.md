# Review response verification — 16 November 2026

Version 0.5.6 is prepared for the review of the submitted 0.5.5 archive. The
WordPress.org submission remains at 0.5.5 until a separate upload is confirmed.
The previous [receipt](wordpress-org-submission.md) and
[verification](review-2026-11-13.md) are preserved as historical records.

## Cause and correction

The reported output sites were already visible as `phpcs:ignore` annotations.
The previous review checked escaping within their shared renderer and treated
that as sufficient justification. It did not enforce the directly inspectable
late-escaping boundary at every caller. A zero-warning configured check therefore
overstated the acceptance of the omitted requirements. The review did not
establish an XSS exploit; the implementation and its acceptance still needed
correction.

All nine direct field-renderer outputs now use native `wp_kses` at the output
site. The separately found Divi error response uses the same principle. Their
policies contain only the actual owned tags and attributes. WooCommerce's
independent block HTML is preserved; only the appended protection fragment is
filtered. No output-escaping suppression remains in production source.

The notice handler no longer accepts a client-selected capability. It changes
only the current user's display preferences through the fixed native
`edit_user` permission for that account, as restoration already did. The nonce
binds the website, provider scope and native user session. Provider identifiers
are sanitized and must equal the bounded original value and the canonical
known-provider list. Native provider access and moderation permissions remain
unchanged. Existing preferences, settings, stored records, schema and signed
protection protocol retain their identifiers and format.

## Acceptance changes

The [development acceptance contract](development-quality.md) separates actual
requirements from configured check results. Its production exception inventory
binds narrow justifications to code and compensating checks; additions and scope
changes fail before packaging. Mutation tests verify that failures are detected,
rather than only testing the accepted inventory.

The general development instructions also require this distinction across
projects. WordPress-specific input/output rules remain in the WordPress workflow;
the repository contains executable regressions and the reviewed exception record.
These changes add no permission to edit original packages or publish a release.
