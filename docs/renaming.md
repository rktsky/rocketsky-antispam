# Name transition in 0.5.1

The public name is **Rocketsky Antispam**. The distribution directory, WordPress.org
candidate slug, Composer package and translation domain use `rocketsky-antispam`.
The entrypoint is `rocketsky-antispam/rocketsky-antispam.php`; the source repository
is [rktsky/rocketsky-antispam](https://github.com/rktsky/rocketsky-antispam).
This does not reserve a WordPress.org slug or submit the plugin for review.

## Existing installations

The previous entrypoint was `wp-antispam/wp-antispam.php`. A changed native
[plugin basename](https://developer.wordpress.org/reference/functions/plugin_basename/)
is a separate activation identity. Upload the new directory, deactivate the old
copy without uninstalling it, then activate the new copy in the same scope.
Activation does not overwrite existing settings. No SQL data migration is needed.

Keep a backup and verify retained data before removing the old directory through
the hosting file manager. Do not run the old copy's WordPress Delete action:
its original uninstall script can delete the same six tables and settings.
The active renamed plugin blocks native uninstall of another identified owned
copy. Its own uninstall also checks other site and network activations before
any cleanup, including activations on other sites in Multisite.

Network activation requires previous individual and network activations to be
deactivated first. Do not change WordPress authentication salts, site IDs, table
prefixes or stored identifiers during this name transition. Those are separate
operations with their own encryption and identity consequences.

## Persistence contract

The stable namespace remains `Rktsky\Antispam`, with `RKTSKY_ANTISPAM_*` constants.
Existing options and metadata retain their `rktsky_antispam` prefix, including
settings, schema version 4, digest state, network schema/cursor and site pass markers.
The existing table suffixes remain:

- `rktsky_antispam_tokens`
- `rktsky_antispam_stats`
- `rktsky_antispam_totals`
- `rktsky_antispam_quarantine`
- `rktsky_antispam_feedback`
- `rktsky_antispam_jobs`

Quarantine key derivation, feedback HMAC inputs and the token protocol retain
their original purpose strings and site binding. Existing ciphertext remains
readable; used tokens remain spent; outstanding unexpired tokens retain their
scope. Native comment/provider records and persistent `rktsky` source identifiers
are unchanged. Newly generated provider notices and spam attribution labels use
the new public name; existing provider logs are not rewritten. The REST namespace
stays `rktsky-antispam/v1`, and frontend field names, WooCommerce extension IDs,
asset handles and `rktsky` CSS selectors stay stable.
The existing REST rejection error code `wp_antispam_rejected` also stays stable
for clients that already handle it; it is not a visible product name.

The per-site and network cron hook names remain unchanged. Normal deactivation
stops the old copy's schedules; activation restores the appropriate schedule.
A native silent upgrader handover can preserve an existing site event's due time.
No additional recurring job is introduced by the rename.

## Loader and lifecycle boundaries

A small independent installation guard runs before shared classes and constants
are loaded. It detects another owned active copy through native activation options
and its identifying plugin headers. Activation then stops before Core records the
new basename. If a legacy and renamed copy already appear together in an activation
list, the renamed loader yields to the legacy copy before shared definitions.
The installed original is never patched.

Native activation permissions prevent reactivating an obsolete copy while the new
one is active. On WordPress 6.9 and newer, the documented requirements filter also
rejects a direct programmatic activation before sandbox inclusion. Older WordPress
versions protect native administration/REST activation; privileged code bypassing
native capability checks must follow the documented handover order.

The native `pre_uninstall_plugin` hook is an action. The guard terminates the
conflicting uninstall before the old script runs; returning a value would not
prevent deletion. All activation checks use documented options, metadata and
lifecycle APIs; no Core/provider SQL or activation-option rewriting is added.

## Translations and links

All bundled catalogues and filenames use the new text domain. English remains the
source language, with German, French, Italian and Spanish catalogues, including
both German locales. External custom language files are left untouched and need
their domain/filename adjusted separately. The administration page uses
`options-general.php?page=rocketsky-antispam`; links generated by the plugin use
that destination.

Historical verification artifacts keep their original filenames. They are evidence
for the version that generated them, not current distribution names.
